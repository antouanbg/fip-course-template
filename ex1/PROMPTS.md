# PROMPTS.md — Как се работи с AI агент в този курс

В Codespaces: **Gemini CLI** (`gemini` в терминала — препоръчително) или **Copilot Chat** (панелът вдясно). Извън тях: **Claude** / **ChatGPT** уеб чат с copy-paste. Инструментът не е важен — важен е начинът на работа. Агентът в Codespaces чете `AGENTS.md` сам; в уеб чат го paste-вате заедно с файла.

## 1. Ролите

| Вие | Агентът |
|---|---|
| Формулирате задачата и ограниченията | Предлага код и обяснения |
| **Проверявате** на контролни точки и тествате | Може да греши уверено |
| Решавате какво влиза в кода | Не познава контекста ви, ако не му го дадете |
| Отговаряте за всеки ред при защитата | — |

## 2. Анатомия на добър prompt

```
[КОНТЕКСТ]   Работя по учебна задача: една HTML страница с vanilla JS, която прави
             fetch() към публично API. Ето целия файл: <paste index.html>
[ЗАДАЧА]     Добави обработка на грешки към click handler-а.
[ОГРАНИЧЕНИЯ] Само vanilla JS, без библиотеки и frameworks. Един файл. Запази
             съществуващата структура и имена. Не променяй нищо извън <script>.
[РЕЗУЛТАТ]   Върни само променения <script> блок + 3 изречения какво и защо си променил.
```

Лош prompt: *„направи error handling"*. Добър prompt: горният. Разликата е **контекст + ограничения + формат на отговора**.

## 3. Готови prompt-ове за Упражнение 1

**B1 — Обясни**
> Ето `<script>` блока: `<paste>`. Обясни ред по ред какво прави. Специално: какво връща `fetch()`, защо има два `await`, какво е `response.json()`. Без да пренаписваш кода.

**B2 — Грешки**
> `<paste файла>`. Добави `try/catch` и проверка на `response.ok`. При грешка покажи разбираемо съобщение в `#joke` с клас `error`. Обясни: каква е разликата между HTTP 404 и мрежова грешка за `fetch()` — в кой случай се влиза в `catch`? Само vanilla JS, само `<script>` блока.

**B3 — UX**
> `<paste>`. Докато заявката тече: `disabled` бутон и текст „Loading…". След успех: добави шегата най-отгоре в `<ul id="history">`, максимум 5 елемента. Използвай `finally` за връщане на бутона. Без библиотеки.

**B4 — Търсене**
> `<paste>`. Добави `<input id="q">` и бутон Search, който вика `https://api.chucknorris.io/jokes/search?query=<q>`. Отговорът е `{ total, result: [{ value, ... }] }`. Покажи `total` и списък с `value`. Обработи празен вход, `total === 0` и специални символи в query. Обясни защо е нужен `encodeURIComponent`.

**Debug (когато нещо не работи)**

**Review (преди push)**
> Прегледай този код като строг code reviewer: `<paste>`. Има ли излишни неща, грешки, лоши практики? Не пренаписвай — само списък с бележки.

## 4. Чеклист преди да приемете AI код

- [ ] **Работи ли?** Пуснах го и натиснах бутона.
- [ ] **Прави ли само поисканото?** Няма добавени библиотеки, frameworks, CDN линкове, „подобрения", които не съм искал.
- [ ] **Тествах и грешния път** — не само „щастливия" сценарий.
- [ ] **Разбирам всеки ред.** Ако не — питам „обясни ред X", докато разбера, или го махам.
- [ ] **Съответства на кода ми** — същите имена, стил, структура; не е паралелна версия.
- [ ] **Записах сесията** в `AGENT_LOG.md` (goal / delegated / checkpoints / went wrong / changed by hand) и ред в `USAGE.md`.

## 5. Типични грешки на агентите — какво да следите

- Смесва `.then()` с `async/await` без причина.
- Забравя `response.ok` — вярва, че `fetch` хвърля при 404 (не хвърля).
- Добавя `mode: "no-cors"` „за да мине" — това скрива отговора, не решава проблем.
- Измисля полета в JSON-а, които API-то не връща → **винаги проверявайте отговора в браузъра/DevTools първо**.
- Пренаписва целия файл при молба за малка промяна.
- Влага `<script>` библиотеки (jQuery, axios) за нещо, което `fetch` прави с един ред.

## 6. Spec first (Бонус C; от Упр. 2 — задължително в `SPEC.md`)

Преди да пишете или генерирате код — 5–8 реда спецификация:

```
Цел:        страница показва случайна снимка на куче при клик
Endpoint:   GET https://dog.ceo/api/breeds/image/random
Отговор:    { "message": "<url на снимка>", "status": "success" }   ← проверено в браузъра
UI:         бутон "New dog", <img id="dog">, съобщение при грешка
Грешки:     response.ok === false или network error → текст в .error, бутонът отново активен
Ограничения: vanilla JS, един файл, без библиотеки
```

После prompt-ът е просто: *„Реализирай по тази спецификация: `<spec>`. Ето текущият файл: `<paste>`."* И проверявате резултата **срещу спецификацията**, не срещу усещането си.
